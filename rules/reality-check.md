# 規則：現實度匹配（reality/<slug>.html）

> 工作流程節點 ⑧（面試後）。動手前先讀完本檔，以及同一 slug 的 jobs、company、career、interview 頁。

## 1. 目的

面試前的分析都是「推敲」；面試是第一次拿到**現場證據**。這一頁要做四件事：

1. **驗證**：先前的推敲哪些被證實、哪些被推翻、哪些仍然不明。
2. **重新評分**：用同一套公式更新適配度、屎缺機率、願景對齊與職涯成長性。
3. **看見隱藏面**：面試中透露、但 JD 不會寫的優缺點，以及進去後 1 個月到 1 年會遇到的狀況。
4. **準備談判**：評估自己的話語權，擬定談薪資與條件的策略。

## 2. 輸入：面試紀錄

### 2.1 存放位置
- `raw/interviews/<slug>-r<輪次>.md`，例：`raw/interviews/2026-11-qingsong-ai-product-specialist-r1.md`
- **真實面試紀錄一律放 `private/interviews/`**：紀錄裡有面試官姓名、公司內部資訊，不可公開。公開網站只放虛構範例。
- 沒有面試紀錄 → **不可產出 reality 頁**（`check.py` 會檢查）。

### 2.2 紀錄格式
```
# 第 N 輪面試紀錄｜<職稱>｜<公司>
- 日期：YYYY-MM-DD｜形式：視訊／現場｜長度：60 分鐘
- 面試官：職稱（不寫姓名）

## 逐點紀錄
- [IV-1] 問到／聽到什麼｜原話或盡量接近的轉述
- [IV-2] ...

## 我的感受（主觀，另外標記）
- 氣氛、面試官的態度、讓我不安或安心的瞬間
```
每一點都要有 `IV-n` 代碼，頁面引用時寫（IV-3）。**頁面上不可出現紀錄裡沒有的面試內容**（`check.py` 會比對代碼）。

### 2.3 網頁上的上傳工具（`intake` 區塊，使用 `assets/reality.js`）
- 使用者可以上傳 `.txt`／`.md` 檔，或直接貼上文字。**檔案只在瀏覽器裡讀取，不會上傳到任何伺服器。**
- 頁面列出先前所有「待確認」項目（來自 company 頁的待確認訊號、career 頁的 ❓、interview 頁的反問題），每項帶 `data-keywords`。
- 讀入紀錄後，自動找出提到這些關鍵字的句子，作為「可能相關的段落」。
- 使用者逐項勾選 ✅ 證實／❌ 推翻／➖ 仍不明，並補上依據。
- 最後匯出 Markdown，存到 `private/interviews/` 交給 AI 產出完整分析。

## 3. 驗證表（`verify` 區塊）

| 先前推敲 | 出處 | 面試中聽到 | 判定 | 影響 |
|---|---|---|---|---|

- 判定只能填：`✅ 證實`、`❌ 推翻`、`➖ 仍不明`。
- 「先前推敲」必須涵蓋：company 頁所有「待確認」、career 頁所有 ❓、interview 頁的反問題，至少 5 列。
- 「仍不明」的項目要寫「下一輪要怎麼問」。

## 4. 重新評分（`rescore` 區塊）

| 指標 | 面試前 | 面試後 | 變動原因 |
|---|---|---|---|
| 適配度 | | | 依 AGENTS.md 第 6 節 |
| 屎缺機率 | | | 依 company-diagnosis.md §5.2，重新逐項計分 |
| 屎缺類型 | | | 機率 > 60% 才填，依控制度 × 回報度 |
| 願景對齊 | ✅n ⚠️n ❌n ❓n | | 重新比對 vision.md |
| 職涯成長性 | 1–5 | 1–5 | 晉升路徑、可學到的能力、團隊是否有人帶 |

- 屎缺機率要附**完整的新訊號表**（同 company 頁格式，`data-signal` 與 `data-trap-total`），`check.py` 會驗算。
- 面試證據可以讓「待確認」訊號正式計分（例：面試官證實前任 < 1 年 → R9 計分），也可以讓原本計分的訊號被推翻而移除。
- **不可只因為面試氣氛好就降低機率**；每一個加減都要有 IV 代碼。

## 5. 隱藏的優缺點（`hidden` 區塊）

分「隱藏優點」與「隱藏缺點」兩欄，各至少 3 點。「隱藏」的定義：**JD 沒寫、面試前查不到、是面試中才透露的**。每點附 IV 代碼。

## 6. 未來會遇到的狀況（`scenarios` 區塊）

| 時間點 | 最可能遇到的狀況 | 機率（高／中／低） | 你可以先準備什麼 |
|---|---|---|---|
| 到職 1 個月 | | | |
| 3 個月 | | | |
| 6 個月 | | | |
| 1 年 | | | |

再加一列「最壞情況」：最糟可能發生什麼、出現什麼訊號就該離開。

## 7. 話語權（`leverage` 區塊）

5 個因子各 1–5 分，平均 = 話語權指數（四捨五入到小數 1 位）：

| 因子 | 問的問題 | 1 分 | 5 分 |
|---|---|---|---|
| 公司急迫度 | 他們多急？ | 不急、候選人多 | 缺口在燒、反覆刊登 |
| 你的稀缺性 | 你有多難被取代？ | 誰都能做 | 團隊缺、市場少見的組合 |
| 替代方案（BATNA） | 談不成你還有什麼？ | 沒有其他機會 | 有其他進行中或已到手的 offer |
| 時間點 | 現在談對你有利嗎？ | 對方已有人選 | 對方在關鍵時程前需要人 |
| 資訊掌握 | 你知道多少？ | 不知道薪資範圍與內情 | 知道範圍、前任狀況、預算 |

- 每個因子寫在 `<td data-lev>`，平均寫在 `<td data-lev-total>`（`check.py` 會驗算）。
- 指數 ≥ 4.0 高、3.0–3.9 中高、2.0–2.9 中、< 2.0 低。

## 8. 談薪資與條件（`negotiation` 區塊）

### 8.1 三個數字（必填，單位：月薪元）
- `data-walkaway`：底線，低於這個就不去（依 vision.md 的薪資條件）
- `data-target`：目標，實際想拿到的數字
- `data-anchor`：開價，第一次說出口的數字
- 必須 **底線 ≤ 目標 ≤ 開價**，且開價要有理由（市場行情、職責範圍、稀缺性），不能只是喊高。

### 8.2 薪資以外的條件
依「對自己的價值」排序列出 4–6 項（職稱、試用期目標、遠端、教育訓練預算、到職日、升遷檢視時間……），每項寫「怎麼開口」。

### 8.3 關鍵技巧
至少 5 條，每條包含：**技巧、為什麼有效、可以直接說的話術**。必須涵蓋：
1. 何時談（不要在第一輪主動談薪）
2. 誰先出價（已知範圍時如何定錨）
3. 包裹談判（薪資談不動時換其他條件）
4. 用證據說話（引用自己能解決的痛點，不是自己需要多少錢）
5. 書面確認（口頭承諾一律要求寫進 offer）

### 8.4 不要做的事
至少 3 條。

## 9. 必備區塊 id

`record`、`intake`、`verify`、`rescore`、`hidden`、`scenarios`、`leverage`、`negotiation`、`sources`
